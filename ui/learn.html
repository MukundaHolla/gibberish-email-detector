THE BASICS   ↘
01

Email address

We look at the spelling of an address. In mukunda@gmail.com, mukunda is the username; gmail is the domain label.

02

Flagged & ordinary

Flagged means a person judged the spelling to be gibberish. Ordinary means they judged it ordinary. These are labels, not proof of fraud.

03

Training data

Two lists of examples: one flagged, one ordinary. They are the lessons used to make the model.

04

Model

The saved result of training: a collection of learned numbers that can score a new address. Think of it as a pattern-scoring recipe.

05

Score & threshold

A score is a number from 0 to 1. The threshold is the cutoff: scores at or above it are flagged by the model.

06

Unsure

The detector declines to score when it lacks enough recognizable pieces or cannot process an address. Unfamiliar gibberish can also be unsure.

Before training

Duplicate & conflicting labels +

Two addresses with the same model inputs are counted once. If that input appears in both labeled lists, the labels conflict and training stops until you resolve it.

Username & domain label +

In mukunda@mail.vendor.co.in, the model uses mukunda and vendor. It uses an offline public suffix list to recognize that co.in belongs together.

Character fragment / n-gram +

A short run of 2, 3, or 4 neighboring characters. For mukunda, mu, uk, muk, and muku are examples.

Minimum fragment frequency +

How many training addresses must contain a fragment for it to be kept. With the default of 2, a fragment seen in only one training address is left out. Also called min-df.

Vocabulary & feature +

The vocabulary is the list of kept fragments. A feature is a measurable input, such as how much the username fragment mu contributes to an address’s representation.

Related username group +

Addresses with the same username before a + tag are kept together when splitting. For example, maya@gmail.com and maya+shop@gmail.com stay in the same group, even across providers.

Making a model

Split, fold & data leakage +

A split divides labeled examples into separate jobs. A fold is one of five buckets of related-username groups. Keeping related groups together reduces leakage: accidentally letting information about a test example influence training.

Training, validation & test +

Training learns the weights. Validation chooses a cutoff. The test split evaluates that frozen choice. The walkthrough below shows every example in a small pretend split.

Validation false-alert budget +

While choosing a cutoff, this limits the observed fraction of ordinary validation addresses that can be falsely alerted. The default is 5%. It is a target on that dataset, not a promise for future addresses.

Weight, intercept & logistic regression +

A weight is a learned number attached to a fragment; the intercept is the starting number. Logistic regression is the learning method that adjusts those numbers using all the training labels.

TF-IDF & normalization +

TF-IDF turns fragment counts into numbers, considering how common each fragment is in the training addresses. The combined username-and-domain vector is then scaled to unit length before the learned weights are applied.

model.json, report.json & reference cases +

model.json holds the learned recipe and its settings for future scoring. report.json describes how training and testing went. golden.json contains fixed reference inputs and expected outputs to check that scoring is consistent; it does not prove accuracy.

Reading a result

Minimum coverage & unsure +

Fragment coverage asks how many pieces in this address the model recognizes. By default, each part must meet 20%. Below the floor—or with no recognized pieces—the result is unsure, not a score. Lowering the floor may score more inputs but can increase errors.

Scored coverage vs code coverage +

Scored coverage is the share of addresses that receive a score. Fragment coverage is how many pieces within one address the vocabulary recognizes. Code coverage measures which lines of software were exercised by tests; this app does not report it.

Precision, recall & false-alert rate +

Precision asks: of all alerts, how many were truly flagged? Recall asks: of all flagged examples, how many alerted? Ordinary false-alert rate asks: of all ordinary examples, how many alerted? See the 20-address example below.

True flag, false flag & missed flag +

A true flag alerts on an actually flagged example. A false flag alerts on an ordinary one. A missed flag is a flagged example without an alert, including an unsure or score-only result.

Score only & no usable threshold +

The detector can calculate a score, but validation could not find a cutoff that caught a flagged example while staying within the budget. It therefore reports the score without making an alert.

Independent holdout & calibration +

An independent holdout is labeled data not used to train or choose settings. If you tune the cutoff on it, use a new untouched set for the final check. A score is not a reliable real-world probability unless calibration is separately established.
