What exactly is a model?

It’s a saved set of learned numbers: a vocabulary of character fragments, their weights, an intercept, coverage settings, and a cutoff. It is created from the training examples and their labels, not a list of hard-coded “bad” addresses.

Data & preparation

Training data +

The labeled flagged and ordinary addresses used to build a model. Only the training split is used to learn the vocabulary and weights.

Flagged vs ordinary +

Flagged means a reviewer labeled the spelling as gibberish; ordinary means they labeled it ordinary. These labels do not prove fraud or validity.

Username & domain label +

The username is before @. The model also uses the registrable domain label: in mail.vendor.co.in it is vendor, using the public suffix list.

Normalization & model input +

A supported address is lowercased for features. Subdomains and suffixes are not spelling features. Two addresses that produce the same username and domain label are the same model input.

Duplicate & conflicting labels +

Duplicate model inputs count once. A conflict occurs when the same model input has both labels; resolve it before training.

Groups & data leakage +

Related username stems before a plus tag stay in the same split to reduce leakage: information about a test example accidentally reaching training. This does not eliminate all leakage.

Public suffix list +

An offline reference for domain suffixes such as com and co.in, used to find the registrable domain label. It does not verify a mailbox.

Learning & scoring

Character fragment / n-gram +

An overlapping substring of 2, 3, or 4 characters. mukunda includes mu, uk, muk, and muku. Username and domain fragments are separate features.

Minimum fragment frequency +

Also called minimum document frequency or min-df: the number of training addresses a fragment must appear in to enter the vocabulary. Default: 2. Setting it to 1 keeps rarer fragments, with trade-offs.

Vocabulary & TF-IDF +

The vocabulary is the retained set of fragments. TF-IDF combines how often a fragment appears in an address with how common it is in training; the combined vector is normalized before scoring.

Logistic regression, weight & intercept +

The algorithm learns a weight for each fragment plus a starting value called the intercept. It combines them into a margin and converts that margin into a score between 0 and 1. Positive weights push toward flagged.

Score & threshold +

The score is the model’s numeric signal. A score at or above the saved threshold raises a gibberish flag. Changing the threshold changes decisions, not scores. A score is not a verified probability of fraud.

Minimum coverage & unsure +

Fragment coverage is the fraction of fragment occurrences present in the vocabulary. The default minimum is 20% separately for username and domain. Below the minimum—or if no fragment is known—the detector returns unsure, without a score. Novel gibberish can also be unsure.

Score only +

The model can calculate a score but has no usable saved cutoff from validation. It returns a score without a flagging decision.

Testing & interpretation

Train, validation & test split +

Five grouped folds are made: roughly 60% trains weights, 20% selects the cutoff, and 20% tests the frozen model. Small datasets can make these proportions uneven.

Validation false-alert budget +

The maximum observed fraction of ordinary validation examples that may be falsely flagged when choosing a threshold. Default: 5%. A small validation set cannot guarantee that rate in future.

Independent holdout +

Separately collected labeled examples not used for training or model selection. If you tune a threshold on a holdout, use another untouched dataset for the final estimate.

True flag, false flag & missed flag +

A true flag alerts on a flagged example. A false flag alerts on an ordinary example. A missed flag is a flagged example without an alert, including an abstention or score-only result.

Precision, recall & false-alert rate +

Precision = true flags ÷ all alerts. Recall = true flags ÷ all flagged examples. Ordinary false-alert rate = false flags ÷ all ordinary examples. If a denominator is zero, the rate is unavailable.

Scored coverage vs fragment coverage +

Scored coverage is the fraction of addresses that receive a score. Fragment coverage is vocabulary familiarity inside one address. Neither is code coverage, which measures how much code tests execute; this app does not report code coverage.

Model report & reference cases +

report.json records split counts, settings, and measured results. golden.json holds fixed cases used to check consistency. Neither proves future accuracy.
