THE BASICS   ↘
01

Email address

We look at the spelling of an address. In mukunda@gmail.com, mukunda is the username; gmail is the domain label.

02

Flagged & ordinary

Flagged means a person judged the spelling to be gibberish. Ordinary means they judged it ordinary. These are labels, not proof of fraud.

03

Training data

Flagged and ordinary email lists teach the email model. Optional flagged and ordinary domain lists teach a separate domain model.

04

Model

The saved result of training: a collection of learned numbers that can score a new address. Think of it as a pattern-scoring recipe.

05

Score & threshold

A score is a number from 0 to 1. The threshold is the cutoff: scores at or above it are flagged by the model.

06

Unsure

The system cannot make a final decision. A model may lack recognizable pieces, a usable cutoff, or supported input. With two models, one may still have a score even when the final result is unsure.

Before training

Duplicate & conflicting labels +

Two addresses with the same model inputs are counted once. If that input appears in both labeled lists, the labels conflict and training stops until you resolve it.

Username & domain label +

In mukunda@mail.vendor.co.in, the model uses mukunda and vendor. It uses an offline public suffix list to recognize that co.in belongs together.

Character fragment / n-gram +

A short run of 2, 3, or 4 neighboring characters. For mukunda, mu, uk, muk, and muku are examples.

Minimum fragment frequency +

How many training addresses must contain a fragment for it to be kept. With the default of 2, a fragment seen in only one training address is left out. Also called min-df.

Vocabulary & feature +

The vocabulary is the list of kept fragments. A feature is a measurable input, such as how much the username fragment mu contributes to an address’s representation.

Related username group +

Addresses with the same username before a + tag are kept together when splitting. For example, maya@gmail.com and maya+shop@gmail.com stay in the same group, even across providers.

Making a model

Split, fold & data leakage +

A split divides labeled examples into separate jobs. A fold is one of five buckets of related-username groups. Keeping related groups together reduces leakage: accidentally letting information about a test example influence training.

Training, validation & test +

Training learns the weights. Validation chooses a cutoff. The test split evaluates that frozen choice. The walkthrough below shows every example in a small pretend split.

Validation false-alert budget +

Each model chooses a cutoff using its own validation data. The default budget is 5% ordinary false alerts per model; the combined rate can be higher. This is a target on validation data, not a promise for future addresses.

Weight, intercept & logistic regression +

A weight is a learned number attached to a fragment; the intercept is the starting number. Logistic regression is the learning method that adjusts those numbers using all the training labels.

TF-IDF & normalization +

TF-IDF turns fragment counts into numbers, considering how common each fragment was in that model’s training data. The email model scales its username-and-domain-label features together. The optional domain model scales its own domain features separately.

model.json, report.json & reference cases +

model.json holds the learned recipe and its settings for future scoring. report.json describes how training and testing went. golden.json contains fixed reference inputs and expected outputs to check that scoring is consistent; it does not prove accuracy.

Reading a result

Minimum coverage & unsure +

Fragment coverage asks how many pieces the model recognizes. By default, the email model checks each part against 20%; the domain model checks its own fragments. A model may be unsure if coverage is too low or no cutoff exists. In a two-model result, an alert from either still flags the address.

Scored coverage vs code coverage +

Scored coverage is the share of addresses that receive an email-model score. With two models, combined decision coverage measures how many get a final flagged or ordinary decision. Fragment coverage is how many pieces within one input the model recognizes. Code coverage measures which lines of software were exercised by tests; this app does not report it.

Precision, recall & false-alert rate +

Precision asks: of all alerts, how many were truly flagged? Recall asks: of all flagged examples, how many alerted? Ordinary false-alert rate asks: of all ordinary examples, how many alerted? See the six-address example below.

True flag, false flag & missed flag +

A true flag alerts on an actually flagged example. A false flag alerts on an ordinary one. A missed flag is a flagged example without an alert, including an unsure or score-only result.

Score only & no usable threshold +

A model can calculate a score, but validation could not find a usable cutoff within its budget. It cannot make a flagged-or-ordinary decision from that score. In a two-model result, if neither model flags and one lacks a cutoff, the final result is unsure.

Independent holdout & calibration +

An independent holdout is labeled data not used to train or choose settings. For two models, keep both addresses and their registrable domains independent of both training datasets. If you tune a cutoff on it, use a new untouched set for the final check. A score is not a reliable real-world probability unless calibration is separately established.

TRY THE DECISION

What if the models disagree?

Choose a situation. These are imagined answers, not predictions from the demo.

Why two models? The email model considers username and domain-label patterns together. The optional domain model learns from separate domain labels and includes the registrable suffix. For name@mail.example.co.in, the domain model analyzes example.co.in. This handles subdomains by using the same registrable domain, not by looking up an uploaded domain.
What about accuracy? Each model is split and evaluated separately during training. Each selects a cutoff using its own false-alert budget, so the combined false-alert rate can be higher. To measure both together, use Evaluate a model on labeled addresses and domains kept independent from both training datasets.
